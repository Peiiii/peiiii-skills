# 远程 Claude Code：连接、等待与续作

让用户直接与原远程会话对话，或由当前协调会话推动已授权任务完成。先区分用户要的是**交互终端**还是**任务跟进**，两者可以共存；用户要求交互时，交付真正可输入的 SSH 终端。

## 最小上下文

从当前任务、项目检查点及已有 SSH 配置解析远端、项目目录、会话 ID、最近用户要求与交付边界。不要把上次运行的 PID、主机、机器路径、凭据或额度恢复时刻固化进 Skill。

跨时间任务在原项目的私有检查点记录：会话 ID、角色分工、最新范围、最后证据与游标、额度恢复的绝对时刻及时区、下一检查点、完成条件。日志和凭据留在忽略目录；Git 跟踪的交付文档只保留可公开的结果与证据。

## 连接与恢复

1. 用有超时的 SSH 只读检查确认到达正确机器和目录。先确认原会话是否存活、忙碌、等待对话框或空闲；元数据可能陈旧，需与真实进程、启动时间及新日志交叉确认。
2. 原会话忙碌就保留它。不要为展示窗口而终止任务；不要开启第二个写入同项目的 Claude，也不要触碰其他项目会话。
3. 需要恢复时，在**远端**项目原工作目录启动 `claude --resume <session-id>`，保留原会话上下文。仅在用户已明确授权相应任务跳过权限时增加 `--dangerously-skip-permissions`；不把这项选择变成其他任务的默认授权。
4. 用户要求独立终端时，优先使用已验证的本机终端启动器，其内部执行 `ssh -tt`；不是本机 Claude，也不是远端桌面另开窗口。参数引用与远端 shell 必须匹配，先核对已有可用启动器再复用。
5. 完成真实出现的恢复对话框，确认提示符可输入、会话身份正确及权限模式符合用户要求。`open` 返回成功或进程存在都不足以证明“终端好了”。

一键打开指定会话、重开前关闭失效窗口或 SSH 断线重连时，按 [独立终端的启动与清理](references/terminal-lifecycle.md) 操作。辨认目标时优先复用已验证的本机启动器及原任务的连接记录；同一机器上的最新会话不能替代指定会话。

Windows 经 SSH 的 PATH、ConPTY 和 Git 特例，只有命中时才读 [Windows 连接排障](references/windows-ssh.md)。其他环境用现有的 tmux、SSH 或会话控制工具，不强套 Windows 实现。

## 当前会话等待，醒来后续作

**这是工具挂起后继续同一轮执行，不是新建 cron，也不是模型一刻不停地检查。** 等待期间远端进程可以独立工作；额度用尽时则等待可续作的时刻。协调方并未承诺应用退出、主机会话终止或工具失效后仍会唤醒。

本次宿主使用 `clock.sleep`，参数为 `duration_ms`，例如 `clock.sleep({"duration_ms": 60000})`。工具调用挂起当前执行，计时结束或新用户输入到来时返回，随后同一会话继续调用 SSH 检查。等待本身不需要反复调用模型；这不代表整个任务没有上下文或工具成本。先确认当前宿主确实提供此工具，再使用其当次文档规定的上限。

- 宿主有可中断等待工具时，已授权单项任务优先留在当前会话完成。先核对工具是否支持新用户消息提前结束等待、单次时长上限与宿主约束。等待返回后继续执行；不要先发 final 再声称还在当前回合等待。
- 额度恢复：读取实际提示，按提示时区转换为带日期的绝对时刻；不能把远端“18:10”直接当成本地时间。用当前时钟计算剩余时间，醒来后重新核对实际额度/状态，时间到了不等于额度一定已恢复。
- 正常运行：按用户要求的间隔检查，例如每小时一次；已知恢复时刻到来则在该点检查。不要在长等待期间另开高频进度轮询，也不重复报告未变化的状态。
- 用户在等待中发消息：先处理其纠正、问题或取消。工具提前返回不代表预定时刻已到，重新算剩余时间；取消时立即停止续作。
- 用户明确要长期或跨会话定时职责时，沿宿主正式调度能力处理。若宿主禁止为单项任务建自动化，保持当前任务等待；能力不足时说明真实恢复条件，不用后台 shell/自制 cron 绕过限制。

### 每次醒来只做一次必要状态判断

| 实际状态 | 动作 |
| --- | --- |
| 新工具调用或日志证明仍在执行 | 更新检查点，按既定间隔等待 |
| 额度仍受限 | 记录新的真实恢复时刻，继续等待 |
| 原会话空闲、任务未完成且额度可用 | 先确认没有用户草稿；发送一次最小续作交接，确认产生新执行证据 |
| 进程退出或 SSH 断线 | 先只读诊断；按原会话 ID 恢复，不重建项目或从头派工 |
| 真正缺用户输入或授权 | 说明最远有效结果与唯一必要条件；不代替用户批准 |
| Claude 报告完成 | 转独立验收；不是直接结束 |

续作交接只带接收方必须行动的信息：保持最新用户范围、仍由 Claude 实现、当前未完成项、交付条件。保留其设计判断，不借恢复追加 UI 限制或无关需求；旧计划不得覆盖后来的用户指令。检查“已忙碌”之外的新工具/日志证据，避免文字已粘贴但未真正发送。

## 独立验收与停止

- 按任务合同核对实际代码、提交推送、需要时的部署，以及用户可操作的关键流程。额度恢复、进程存活、Claude 自报通过分别只是局部证据。
- 用户给了界面设计参考时，把功能验收与视觉验收分开：以用户认可的具体画面为基线，在同一手机视口和相同内容下对照实际运行截图，检查布局、密度、层级及关键组件；实际打开图片不等于已落实参考，功能通过也不能替代视觉落地。交付前明确采用与偏离之处及理由；主要参考关系没有体现时，交回实现者返工，不能仅以“自主取舍”宣告完成。此门槛来自一次已读图却只做局部样式调整的真实漏验，修复效果保持 pending-real-use，直到后续类似交付实际通过。
- 不必重跑所有未受影响检查；选择能验证改动与真实风险的检查。生产验证只用可识别的自建临时数据并精确清理，不改用户原数据。
- 发现实质问题交回原 Claude 会话修复，保留用户指定的实现者。修复后验证失败场景及受影响流程；未经用户改派，不悄悄接手实现。
- 交付通过后更新原检查点为完成，清空下一检查时间并停止等待循环。如果确实存在本任务的调度，核对身份后按宿主能力停用/删除；没有创建自动化就说“已停止后续检查”，不要虚构取消回执，也不要停掉同项目的其他任务。
- 最终提供可用入口、实际完成结果和材料性未测边界。终端可保留给用户继续对话，停止跟进不等于杀掉 Claude。

## 经验的验证范围

上述流程来自一次真实远程协作：额度耗尽后通过当前会话可中断等待续作；SSH 断线后恢复同一会话；独立验收发现失败重试丢输入，交回 Claude 修复、验证并部署后停止检查。连接与验收流程已经实际使用；本 Skill 的后续真实调用效果仍需观察。它不提供后台持久唤醒保证。
