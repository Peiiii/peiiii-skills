# 独立终端的启动与清理

## 一键打开原会话

1. 从既有启动器与原任务交接核对所选会话的 SSH 别名、远端启动目录、保存原历史的会话 ID 及权限模式。如果用户通过另一段 Codex 对话指代它，先查那段对话实际连接的记录。快捷入口只绑定用户指定的会话，配置和日志留在本机私有目录。
2. 在开任何窗口前，对同一别名做有超时的非交互 SSH 探测，检查认证通过且远端命令确实返回成功。使用有上限的重试。失败时保留原会话，汇报具体环节，不打开失败窗口。多窗口连到同一台主机且可使用 OpenSSH 复用时，用权限受限的本地 `ControlPath` 配合 `ControlMaster=auto` 和 `ControlPersist`，让窗口复用探测通过的连接。设置 SSH 保活，链路断开时重新验证并按原 ID 恢复，不自动重发上一条消息。
3. 成功后，在各自远端工作目录用 `ssh -tt` 进入原生 Claude Code `--resume` 界面。一个本机命令可批量打开指定列表，每个会话一个独立窗口。复用已打开且正确的窗口；重开前检查原进程状态，忙碌、待审批或存在用户草稿时保留，避免同一会话并发写入。权限模式按各会话授权解析。
4. 对启动时实际显示的提示按语义处理。已授权恢复原会话时，`Resume this conversation?` 可选择保留原历史的 `Resume`。若该版本明确显示 `Esc to resume`，可以按该提示恢复。自动化仅匹配这段启动对话框并限定时间、次数；出现购买用量、信任目录等其它提示时，按各自授权边界处理。历史中的旧限额消息不足以说明当前仍不可用。

## 关闭失效窗口并验证

1. 本机按终端应用、TTY 和进程树查清窗口用途。用远端的会话 ID、真实 PID 和状态区分活跃会话、审批等待与失效连接。失效启动器可能只剩停在错误提示的本机 shell，仍在运行的 SSH 或远端任务不能据此一并清理。
2. 只关确认失效的窗口。用户明确要求先关掉所有独立终端时，检查应用下仍有无有效作业，再关闭范围内的终端应用；保留其它应用、会话记录、配置和仓库。需要终止进程时核对其身份和子进程，只处理对应窗口或经授权退出的应用。
3. 在 macOS 上，退出 Terminal 后按普通方式打开可能恢复上次的窗口。用户已授权清掉旧窗口且 Terminal 已退出时，用 `open -F -a Terminal` 加上经过验证的启动文件路径，一次传入目标列表。`-F` 让本次启动跳过窗口恢复；Terminal 已运行时用普通打开，保留其中的有效窗口。关闭后核对旧进程已退出，重开后核对窗口数量与目标会话一致。
4. 对每个窗口分别确认原历史和可输入提示，或确认原会话已在正常执行。只看到本机 SSH 进程、远端正在等待对话框、或 `open` 返回成功时，按实际状态回报。两个会话中只有一个就绪时，分别说明结果。

已验证的场景包括 SSH 超时后未创建窗口、全新启动避免恢复旧窗口、两个独立终端恢复各自原会话，以及原生交互中出现的限额相关恢复提示。链路持续不可达时，一键启动只能等待并诊断，实际打开仍取决于 SSH 连接。
