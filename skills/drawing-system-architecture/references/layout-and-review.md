# 布局与检查

## 参考图的有效设计

示例用四个区域分开定义、运行核心、外部业务与执行资源。核心内的代码模块、规则和共享信息各有独立方块，通过具体动作连线；执行区嵌套两台机器，每台展示可扩展的运行时。适合同时解释逻辑职责与部署边界。

可复用的是边界、视觉层级、模块实体和有意义的连线，不是四象限的位置。API 服务可能适合左侧入口、中部业务服务、右侧依赖、下方存储；数据平台可能适合来源、处理、消费与旁侧治理。先选择阅读路径，再安排区域。

## 比参考图进一步改进

- 参考图信息较多：总览优先保留读者最关心的实体，把解释性段落和实现细节放到文档。
- 参考图部分标签贴近箭头：为文字预留独立净空，尽量使用边界端口和正交线路，避免箭头穿过卡片。
- 系统总览与部署图可以拆开，但总览仍显示关键执行边界；不要为“简洁”丢掉读者要求的成员、职责、状态或节点关系。
- SVG 应自包含，无远程字体、外链图片或脚本依赖。使用 viewBox 和实色背景；字体使用跨平台 fallback。默认以 1440–1800 宽度设计只是起点，最终以嵌入后的可读性为准。
- 若 900px 宽度下正文读不清，优先压缩文案、减少层级或分图；必须保留细节时提供放大入口。

## 验证场景

1. 系统只有活动名称：能否识别谁承接活动，缺失处标待定，而不凭空制造调度器？
2. 两台机器可接不同执行器：能否区分角色、runtime 与部署位置，并表示开放扩展？
3. 用户要总览又要详细链路：能否保留一张清晰架构图，另附流程细节？
4. 把样例迁到无关系统（如文件处理服务）：能否保留绘图方法，而不复制组织角色和品牌？
5. 仅讨论系统、不要求绘图，或要求宣传插画：不调用本技能。

检查结果应区分语义审阅、静态文件验证和实际视觉验证，未执行的检查不能标通过。
