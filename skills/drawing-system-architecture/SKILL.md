# 系统架构绘图

按当前绘图请求调用，不主动启动任务、修改系统架构或发布资料。明确架构图要解释的系统与读者，从已有材料中提取事实；不要为了填满方块发明组件。

## 先设计表达

用简短表格或内部草稿列出：实体名称、类型、职责、所在边界、与谁交换什么。类型可为代码模块、角色、配置、共享信息、外部系统、执行节点。配置与资料不伪装成运行进程。

- 模块用名词命名并附一行职责：“任务服务：登记、交接、状态更新”，而非只有“任务与协作”。
- 主图回答“系统由谁承接、怎样连接”；流程解释“先后怎样运行”。必要时另附流程视图，不把所有步骤塞进主图。
- 分层依据职责与接口，不按关键词分组。部署位置与逻辑层分开表达；成员、任务、执行器、机器属于不同概念时分别表示。
- 缺失信息标注待定或设计假设；不能把拟议能力画成已实现能力。

## 自由布局与制作

优先产出原生 SVG：直接编写或生成矢量图，必要时外包一层 HTML 便于缩放。用项目已有工具渲染 PNG 作为兼容备用，不依赖特定本机绝对路径。不用生图模型生成精确架构文字与连线。

首次需要布局参考时，读取 [布局与检查](references/layout-and-review.md)，查看 [示例 SVG](assets/layout-example.svg) 的实际画面。示例展示方法，不是所有项目的结构模板；不要复制其中的组织术语、品牌或模块到无关项目。

1. 按读者首要问题安排主区域，可以左右、上下、侧栏或嵌套，不强制三层纵排。
2. 每块写实体名和短职责；总览保留主要边界与关系，细节移到补充图。
3. 连线标明业务含义，例如“提交结果”“加载规则”“分配任务”。数据流、依赖与部署包含关系不要混用同一种箭头；不同线型必要时配简短图例。
4. 先为跨区连线留走线空间，再放卡片。连线贴合端口，尽量绕边，避开文字。标签有背景底板，避免压在交叉处。
5. 同类区域用统一浅色底与深色字，建议蓝色定义、暖色核心、绿色执行、灰色外部；按项目语义调整。颜色之外仍靠标题、边框与线型辨识。
6. 同类重复实体可用“成员 A/B/C”“机器 A/B”帮助理解，开放集合用省略号；不要暗示列出的示例就是完整支持列表。

## 渲染后再交付

必须实际打开或渲染 SVG 并查看画面。检查正文嵌入宽度与原尺寸两种尺度；文字太小时减少内容或拆图，不只是扩大画布。

核对：模块类型与职责准确、边界清楚、关键关系齐全；箭头起止正确且避开文字；文字不裁切；中文字体可读；明暗背景均可辨。用当前项目的一条实际调用链检查遗漏，但不把整条链逐步编号成主图。

图过密时同时提供总览与细节图。用户认可的版本按 v1/v2/v3 保留，后续新版本不覆盖。交付可编辑 SVG 与必要 PNG，简述图中主要关系和仍待确定处。SVG 可直接嵌入 README，检查链接、体积及实际渲染，避免仅确认文件存在。
